lens: dependencies.

every dependency is code we ship but did not review, compile time we pay daily, and
a supply-chain surface. the leanest line of code is in someone else's crate only
when we use enough of it.

method- for each [dependencies] entry in each crate: list the items we actually
import (grep), estimate the fraction of the crate used, and check whether a sibling
crate already depends on something that covers it. one-function usages of heavy
crates are candidates for a 20-line local implementation- but only when the function
is simple and testable (encoding helpers yes, cryptography absolutely never- hand-
rolling crypto is banned regardless of line count). dedupe versions across the
workspace; check default-features = false everywhere; check dev-dependencies that
no remaining test uses. the kernel just got to blake3+optional crypto- that is the
target profile; measure every other crate against it.

output: per crate, the dependency table (used items, fraction, verdict), then
cargo-tree before/after for the workspace.
